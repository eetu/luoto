A sandbox for dependencies and agents that feels like working locally

Packages, tools and agents reach only the hosts you allowed, with your tokens in a vault outside. It feels like your machine: your editor over SSH, dev servers at localhost, toolchains installed from the project's own files.

Why

A malicious package runs with everything you have. Its install script can read ~/.ssh, your cloud and registry tokens and your other repos, send them anywhere, and use a token of yours to publish itself further. Coding agents run more code, faster, often with their permission prompts off.

luoto gives each project a sandbox where that doesn't work:

It sees only the project.

The project is copied in, with any folder you share; your home folder, SSH keys and other repositories stay on your machine.

It reaches only what you allowed.

Every request leaves through a gate with per-host rules, read-only by default beyond what installs and the agent's model need. Anything else is blocked and shown to you, with a one-click allow.

Your tokens stay outside it.

Agent, git and cloud tokens stay in a vault outside the sandbox; the gate adds them to the requests you allowed, and code inside sees placeholders. A git token over HTTPS clones and pushes only the repositories you named. A secret is inside only where you put it there: a variable the code reads, an agent you log in inside, what a cloud identity reads.

You keep working as usual: your editor attaches over SSH, agents run with their permission prompts off because the sandbox is the boundary, and work leaves by git push or a reviewed luoto pull. Agents know they're in a sandbox: through luoto's MCP server they ask for a host, an install or a variable, and you approve.

Setting up takes no list of tools. luoto init reads the project's own version files (.node-version, rust-toolchain.toml, a package.json's package manager, …) and proposes its toolchains and package registries; luoto up installs them in the env, with the gate open to each install's hosts only while it runs.

Install

macOS, Linux
curl -fsSL https://raw.githubusercontent.com/eetu/luoto/main/install.sh | sh
macOS, Linux Homebrew
brew install eetu/tap/luoto
Linux, no script
a .tar.gz from Releases, checked against SHA256SUMS
Windows Scoop; not yet verified end to end
scoop bucket add luoto https://github.com/eetu/scoop-luoto
scoop install luoto
From source
source builds

Then, once:

luoto setup

It finds the container runtime you have installed, asks which to use when there are several, and gets the images. With none, it lists the ones it supports and their install pages. Updates, tab completion and checking a download: Install details.

Getting started

cd ~/dev/my-app
luoto init                      # an env for this folder, from the toolchains its files name
luoto agent add claude          # installs Claude Code; asks for its credential
luoto agent run claude --yolo   # it works inside; the sandbox is the boundary
luoto open                      # your editor over SSH (or `luoto shell`)
luoto ui                        # what the env reached and what the gate blocked
luoto pull                      # bring files back when you need them here
luoto down                      # stop it; `luoto up` brings it back

A first session goes through it step by step: credentials that stay outside the env, ports, what it reached, a pull request.
